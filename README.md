# Tangent

Tangent is an on-device voice diary for any topic. Record a check-in, read its transcript and
short summary, and review insights based on short summaries and your interests and concerns.
Diary data, transcription, and model inference stay on the device. Model weights
are downloaded from Hugging Face when selected in Settings.

## Requirements

- macOS with Xcode; iOS 18.2 or later.
- An Apple Silicon Mac for the MLX development setup.
- A physical iPhone or iPad for on-device model inference. The simulator supports
  the other app workflows and unit tests.
- Python 3 for the optional environment helper.

## Getting started

From the repository root:

```sh
python3 scripts/environment.py auto --resolve --open
```

Select the **Tangent** scheme and a device or simulator, then run with **⌘R**.
For a physical device, configure your signing team. The helper accepts
`--team YOURTEAMID` or the `TANGENT_DEVELOPMENT_TEAM` environment variable to keep
that setting local.

## Xcode compatibility

| Profile | Swift compiler | MLX LM | MLX Swift | Transformers | Hugging Face |
| --- | --- | --- | --- | --- | --- |
| `xcode16` | 6.0 (tested with Xcode 16.2) | 2.29.2 | 0.29.1 | 1.1.0 | Transformers' Hub API |
| `modern` | 6.1+ | 3.31.3 | 0.31.6 | 1.3.0 | 0.9.0 |

`auto` selects the profile using the active Xcode compiler. To override it, use
`xcode16` or `modern` in the command above. With several Xcode installations,
set `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` for the command.

The modern profile uses `Tangent/Tangent.xcodeproj`. Xcode 16.2 requires the
local `Tangent/Tangent-xcode16.xcodeproj` generated by the helper. Regenerate it
after pulling project changes. A signing override also generates a local copy.
Always edit shared target settings in the original project.

Swift Package Manager resolves dependencies automatically. Keep the shared
`Package.resolved` and the compatibility lockfile in `BuildProfiles` under version
control. Change dependencies deliberately and validate the affected profiles;
do not commit machine-specific project copies, signing changes, or build caches.
The two MLX versions use separate model caches, so switching profiles can require
a model download in Settings.

## Models

Choose a model in Settings and download it before generating summaries:

- [Qwen3 0.6B](https://huggingface.co/mlx-community/Qwen3-0.6B-4bit): compact default, approximately 350 MB.
- [Qwen2.5 0.5B](https://huggingface.co/mlx-community/Qwen2.5-0.5B-Instruct-4bit): smallest option, approximately 300 MB.
- [Qwen3 1.7B](https://huggingface.co/mlx-community/Qwen3-1.7B-4bit): larger general-purpose option, approximately 1 GB.
- Gemma 3 1B: alternative general-purpose model, approximately 800 MB.
- MedGemma 1.5 4B: specialist option, approximately 2.5 GB.

These are supported 4-bit MLX models. Download size is not total runtime memory;
performance depends on the device and input length. Qwen3 thinking mode is
disabled for short diary responses. Existing model selections are retained.

## Development

See [architecture](Tangent/ARCHITECTURE.md) for module responsibilities and
[rules.txt](rules.txt) for app requirements and the database specification.
Keep changes scoped, test the affected workflows, and make focused commits with
messages describing the change. Review `git diff` before committing.

Run **Product → Test** in Xcode, or test the project helper with:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
```

App tests cover diary persistence and migration, summary generation flow, insights,
and export. Model inference needs separate validation on a physical device.
